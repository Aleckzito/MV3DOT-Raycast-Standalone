## 2. Ciclo de vida y memoria en combate (anti-crash)

### Colas de combate (bridge)

| Cola | Tipo | Quién la purga |
|---|---|---|
| `pendingCreatureMeleeImpacts_` | creature → player wind-up | `clearCombatAggroForPlayer`, `purgePendingCombatForCreature` |
| `pendingPlayerMeleeImpacts_` | player → creature wind-up | igual |
| `pendingProjectiles_` | misiles | igual |
| `creatures_` | vector vivo | erase-remove en `markCreatureDeath` |

### Patrón obligatorio onDeath (jugador)

```
contact frame (remove_if sobre pendingCreatureMeleeImpacts_)
  → si HP llega a 0: solo playerDeathsThisTick.push_back(id)
  → NO llamar handlePlayerDeath dentro del remove_if
después del erase:
  → unique + handlePlayerDeath (clearCombatAggro + respawn templo)
```

**Por qué:** `clearCombatAggroForPlayer` borra la misma vector que el `remove_if`
itera → UAF / Access Violation `0xC0000005` si se llama mid-iteration.

### Patrón onDeath (criatura)

1. `purgePendingCombatForCreature(id)`  
2. `creatures_.erase(remove_if…)`  
3. `OP_RC_CREATURE_REMOVE`  
4. `clearPlayerTarget(id)` → `OP_RC_TARGET_CLEAR`  
5. corpse + XP/loot (V20.4)

### Auto-Battle (autoridad servidor)

- `tickPlayerAutoBattle` (cada tick, tras decrementar `attackCooldown`)
- Requiere `playerTargetId` vivo, mismo piso, dist ≤ 1.55, path libre, CD 0
- Unlock por muerte/ausente → `TARGET_CLEAR`
- Unlock por visión > 12 tiles (no spam “Out of reach” en melee)

## 3. Máquina de estados del Target HUD

### Protocolo

| Opcode | Dir | Uso |
|---|---|---|
| `OP_RC_SET_TARGET` 0x1C | C→S | lock / unlock (id=0) |
| `OP_RC_TARGET_CLEAR` 0x3F | S→C | server fuerza unlock |
| `OP_RC_CREATURE_REMOVE` 0x1B | S→C | despawn; cliente limpia mirilla |
| `OP_RC_CREATURE_STATUS` 0x1F | S→C | HP; edge hp→0 → pending clear |

### Flujo cliente

1. Tab / tecla 5 → `cycleTarget` / toggle → `sendSetTarget`
2. `poll` recibe REMOVE / TARGET_CLEAR / STATUS death
3. `GameplaySessionModule`:
   - `pullPendingTargetClear` → clear lock + `sendSetTarget(0)`
   - `pullPendingCreatureRemovals` vs **lock-on vivo** (no solo snapshot de frame)
4. `OsgRenderer::updateCreatures`: si target no está en activeIds →
   `currentTargetId_=0`, `smartHud_.clear()`, `hud_.clearCombat()`

### UI que debe apagarse al morir el target

- Mirilla `[  ]` (`OsgSmartHud::updateLockOn` / `clear`)
- Panel `:: TARGET TELEMETRY ::` (`smartHud_.clear`)
- Combat strip HUD (`hud_.clearCombat`)
